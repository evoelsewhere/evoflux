# Migration board

One row per lane. A lane is one owner, one set of Python sources, one set of
output paths (design §5). The workflow is in [AGENTS.md](AGENTS.md); the
unit a lane belongs to is explained in [CUTOVER_UNITS.md](CUTOVER_UNITS.md).

- **Claim a lane** by opening a draft PR that changes only its row to
  `claimed`, with your agent id in `claimed_by` and today's date in `updated`.
- **`status`**: `open` → `claimed` → `in-review` → `merged` → `cut-over`, or
  `blocked:<reason>`. Rows `blocked:phase-N` open when Phase N ends; the exit
  check (Phase 0 plan, Task 16) opens Phase 1.
- **`unit`**: the cutover unit from `routing.toml`, or `none` for a lane with no
  HTTP routes (CLI, plugin host, skill scripts), which ships with a release.
- **`routes`**: the route patterns the lane ports. `/**` covers the prefix and
  everything below it; the longest pattern wins. Together the lanes cover every
  route FastAPI registers, and each route's lane must be in its unit.
- **`owned_paths`**: comma-separated globs. CI (`check_paths.py`) rejects a lane
  PR that touches anything else. `server/MIGRATION_BOARD.md` itself is allowed
  for the lane's own row. Phase 0 rows (`p0-*`, area `shared`) list only files
  the task creates or edits alone, so the task that creates `server/Cargo.toml`
  or `contract-tests/conftest.py` owns it; files that later tasks also edit
  (`Makefile`, `.gitignore`, `pyproject.toml`, CI workflow additions) are not
  owned by anyone. The `web-ui` lane's `/**` is the catch-all for the packaged
  web UI; it never counts as owning an `/api` route.
  Phase 0 `claimed_by` shows `(assigned)` while the row is still `open`.
- **`python_sources`**: where to read the behaviour. Not checked by CI.
- **`gate_report`**: link to the latest gate report, `-` until there is one.
- Run `uv run python scripts/migration/check_board.py` before changing this
  file. `--status` prints the lane counts.
