# Document design and layout

Use this reference for a new DOCX or a user-requested major redesign. For a
narrow edit, preserve the source document instead.

## Define the document system

Choose the document job before formatting: memo, proposal, report, guide, SOP,
form, workshop plan, or reference. Define one coherent token map for page size
and margins, typography, paragraph rhythm, list indents, color roles, table
treatment, callouts, headers, and footers. User instructions and supplied brand
or template evidence override defaults.

Use real Word styles and numbering so hierarchy and navigation survive edits.
Apply the same semantic role consistently; record deliberate exceptions rather
than accumulating direct-formatting drift. Test every required language and
glyph set with the actual fonts available to the renderer.

## Match information to form

- Use prose for an argument or explanation.
- Use numbered steps for sequence and bullets for non-sequential choices.
- Use a checklist for action tracking and a note or warning box only for a
  message that must interrupt the reading flow.
- Use a definition list for short term/value pairs.
- Use a table only when readers need genuine row-and-column comparison, data
  entry, status, schedule, or a matrix.
- Use a form layout for responses; do not make a questionnaire look like a
  dense spreadsheet.

Audit every table with the question: would headings plus prose or a short list
communicate this more naturally? Never use tables merely to create columns,
cards, section bands, or paragraph containers.

## Layout and table geometry

Calculate usable width from each section's page size and margins. Set column
widths by content rather than equally by default. Allow rows to expand; never
use a fixed row height that can clip text. Prefer wrapping, width adjustment,
or shorter labels before shrinking type.

Give cells deliberate padding and vertical alignment. Align narrative text
left and choose alignment for dates, numbers, statuses, and short values by
their meaning. Repeat a real header row when a table spans pages, keep captions
with their table or figure, and prevent lone headings at page bottoms.

Keep the first page appropriate to the document job: a compact memo masthead,
a proposal title block, an editorial cover, an operational pack header, or a
simple title. Use exactly one opening pattern. Avoid decorative furniture that
does not help the reader identify purpose, ownership, date, or status.

## Visual quality gate

Render every page after each meaningful layout batch and inspect at normal
reading size and at full size. Check:

- hierarchy, paragraph rhythm, balanced whitespace, and consistent margins;
- clipping, overlap, missing glyphs, unexpected wrapping, and blank pages;
- headings, lists, table widths, row expansion, cell padding, and alignment;
- image resolution, captions, alt text, headers, footers, and page fields;
- page breaks, widows/orphans, split tables, and recurring elements.

Fix the authoring source and rerun it; do not patch only a preview. Deliver only
the final DOCX. If no DOCX renderer is available, complete structural checks
and disclose that visual QA was not performed.
